# 021 点资料卡 ⇒ 右侧抽屉直接显示源文件

## 要解决的问题
owner 2026-09-26：「点击资料库文件连接的时候，右侧的抽屉直接显示对应源文件。」
上一版（020）按他前一句「点击了资料的连接就该可以阅读原件。而不是简单的目录」把点卡改成**跳去阅读页**；原来的抽屉里放的是**目录**。
两句合起来要的是：**留在列表旁边（抽屉）、而抽屉里是原件（不是目录）**。

## 方案
```
资料库列表                     │ 右侧抽屉（可拖宽窄，Esc / × 关闭）
┌─────────────┐               │ [规范] 资料预览      [加入项目][全屏阅读] ×
│▣ 数据质量…   │ ← 点           │ 数据质量 评估指标体系与方法规范
│  煤矿…       │               │ 出处：抓取车道 ttbz-fulltext · 取回于 … · 所在页面 · 文件原址
│  …           │               │ − 100% + │ ✋ 📏 ⌖ │ 💬0 ⊙0 👁          第 1/1 页
└─────────────┘               │ ┌──── PDF 原件 ────┐
                               │ └─────────────────┘
```
- 规范 / 图集 / 杂志：抽屉里是 PDF 原件（与阅读页同一个 PDF.js 查看器，只读）。
- 媒体：抽屉里是原文，图按原文顺序插在对应位置。
- 从**对话引用**打开（带段落 id）仍先给命中段落与目录 —— 那里要的是「判断是不是这一条」。
- 查看器工具栏改用**容器查询**（`@container`）：按查看器自己的宽度决定显不显示「浏览 / 测量」等文字。窗口宽、抽屉窄时只剩图标（悬停有提示），全屏阅读时文字照常。

## 用到的设计知识
- **主从布局（List–detail / master–detail）**：列表不离开视野，右侧看详情；邮件客户端、Finder 预览栏、Figma 资源面板都是这个模式。
- **容器查询（CSS Container Queries，2023 起主流浏览器都支持）**：组件按「自己被放进的盒子」响应式，而不是按整个窗口 —— 同一个查看器放在全屏和抽屉里都合适。

## 备选方案与取舍
| 方案 | 结论 |
|---|---|
| 点卡跳阅读页（020） | 不用：离开列表，对比几份要来回跳 |
| 抽屉里放目录，再点进原件（更早的做法） | 不用：owner 两次说要直接看原件 |
| 抽屉里放缩略图 | 不用：看不清条文，还得再点一次 |
