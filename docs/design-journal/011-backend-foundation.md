# 011 后端地基（第 ③ 步）：数据存进数据库

## 已定下来的

| 项 | 决定 |
|---|---|
| 先做什么 | 把服务器内存里的数据存进数据库，重启不丢（负责人同意开始第 ③ 步） |
| 数据库 | 先用 **SQLite**（Node 自带，一个文件），人多了再换 PostgreSQL |

## 方案

```
之前：服务器内存 ──重启──▶ 全部清空（大家要重新登录，改过的项目、权限都丢）
现在：.data/imagination.db ──重启──▶ 还在
```

| 数据 | 之前 | 现在 |
|---|---|---|
| 成员名单、账号状态 | 内存 | 数据库 |
| 登录会话（1 电脑 + 1 手机） | 内存 | 数据库：重启后不用重新登录 |
| 验证码 | 内存 | 数据库（只存哈希） |
| 账户偏好（对话模式） | 内存 | 数据库 |
| 项目、成员权限 | 内存 | 数据库 |
| **项目依据清单** | **各人浏览器本地（成员之间其实看不到彼此加的）** | **数据库：项目成员共享** |
| 个人文件的访问权限 | 内存 | 数据库 |
| 查看记录 | 内存 | 数据库（只增不改，永久保留） |
| 笔记本、个人标注、上传记录 | 浏览器本地 | 暂不变（下一批） |

- **备份**：`npm run db:backup`，生成一份带时间的完整副本（服务器运行中也能做）。
- **换数据库**：所有读写都经过 `src/lib/server/db.ts` 的 `collection()`；以后换 PostgreSQL 只改这一个文件。

## 用到的知识

- **SQLite**：把整个数据库放在一个文件里的数据库，不用单独安装服务。手机 App、浏览器、很多桌面软件都在用；几十人使用完全够。
- **文档表**：每条记录存一段 JSON，字段变化时不用改表结构，适合还在快速调整的阶段。代价是复杂查询不方便，等数据结构稳定后再拆成正式的表。
- **持久化**：数据写到磁盘上，断电、重启都不会丢。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| SQLite（一个文件） | 零安装、备份就是复制文件、够 5–50 人用 | 多台服务器同时写不方便 | **现在采用** |
| PostgreSQL | 正式、可扩展、查询强 | 要单独装和运维 | 人多或上多台服务器时再换 |
| 云数据库（托管） | 不用自己运维 | 费用；数据放在外部 | 待定 |

## 待你决定

- [ ] **服务器放在哪里？** A 公司内网（和群晖 NAS 同一个网络） / B 云服务器（阿里云、腾讯云等） / C 先放云上试用，稳定后搬回内网。推荐 **C**：试用阶段方便大家在外面也能用，正式上线时再按数据安全要求决定。
- [ ] **自动备份频率？** A 每天一次，保留 30 天 / B 每小时一次，保留 7 天。推荐 **A**，另外每周复制一份到 NAS。
