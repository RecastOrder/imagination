# 000 地基：令牌、组件分层、页面骨架

## 要解决的问题

让以后“改一个效果只动一处”，不会牵一发而动全身。

## 方案

```
L4 页面      src/app/…                   首页、对话、资料库、阅读、设计样张
L3 骨架      components/shell            AppShell（侧栏+主区）、PeekLayout（主区+预览）
L2 业务组件  components/{chat,blocks,…}   Composer、消息、资料卡片、筛选、阅读器
L1 基础组件  components/ui               Button、Badge、Input、Sheet、Tooltip、Resizable
L0 设计令牌  app/globals.css             颜色、圆角、字体、阴影
```

令牌三层：**原始值**（`--terracotta-600`）→ **语义**（`--primary`）→ 组件只认语义。
暗色模式 = 在 `.dark` 下重新映射语义层，组件零改动。

打开 `/design` 可以看到所有令牌和组件状态的“活样张”。

## 用到的设计知识

- **设计令牌（Design Token）**：把颜色、间距等设计决定写成有名字的变量。出处：Material 3 的 ref / sys / comp 三层令牌。
- **语义命名**：变量名描述“用途”（背景、主操作），而不是“长相”（浅灰、橙色）。换色时名字不用改。
- **变体（Variant）**：同一组件的几种预设外观，由组件自己定义。页面只能挑，不能改。
- **克制用色**：强调色只用在“主操作 / 当前位置 / 焦点”三处，越少用越醒目。出处：Refactoring UI 的“Use color sparingly”。
- **雅各布定律（Jakob's Law）**：用户大部分时间在用别的产品，所以左侧栏 + 底部输入框这类布局沿用 ChatGPT / Claude 的惯例。

## 已定下来的

| 项 | 取值 |
|---|---|
| 中性色 | 暖石材灰（stone），占界面约 90% |
| 强调色 | 陶土色 `oklch(0.555 0.14 40)`，暗色下用更亮的 400 |
| 字体 | 界面用无衬线；阅读用衬线宋体 |
| 字号 | 12 / 14 / 15（正文）/ 18 / 24 / 32 |
| 间距 | 4 的倍数 |
| 圆角 | 由 `--radius: 10px` 推导出 sm 6 / md 8 / lg 10 / xl 14 / 2xl 18 |
| 层次 | 优先用边框，阴影只给浮层（输入框、抽屉） |
