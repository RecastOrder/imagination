# 022 原件按页宽显示 · 放大镜 · 开抽屉时自动让出宽度 · 按打开次数排序

## 要解决的问题
owner 2026-09-26 晚：
- 「源文件在读取的时候要注意页面宽度。不能只显示局部。增加放大镜图标，局部放大就可以一下子就放大了。」
- 「在阅览资料库的时候，点击链接打开右侧抽屉时，如果宽度不够，可以让导航栏自动收回去。」
- 「显示的规范图集杂志或者媒体都按照搜索的次数排序，搜索次数多的多往前面排」

## 方案
```
开抽屉前（1440 宽）                         开抽屉后
┌──────┬────────┬─────────────┐           ┌─┬──────────────┬───────────────────────┐
│导航  │筛选栏  │ 资料列表     │    ⇒      │▮│[筛选 1] 列表  │ − 95% + ↔ 🔍 │ ✋ 📏 ⌖ │
│256px │208px   │             │           │▮│              │ ┌── 原件：整页宽 ──┐  │
└──────┴────────┴─────────────┘           └─┴──────────────┴─└──────(○镜片)────┘──┘
```
- **适应宽度（fit-to-width）是默认**：原件按查看器的宽度整页放下，拖宽窄抽屉、改窗口大小都跟着重算；± 从当前比例往上/下跳一档，「↔」回到适应宽度。
- **放大镜（loupe）**：工具栏 🔍 开关；指针指到哪里，圆形镜片（240px）里就把那一块放大 2.5 倍。镜片用单独按放大倍数渲染的高清页面，文字不糊。
- **导航栏让位**：开抽屉时，屏宽 < 1920 就把左侧导航收成图标栏（原来是 < 1536）。
- **筛选栏让位**：资料库筛选栏按资料库自己的宽度显示（容器查询 `@container`），抽屉一开、列表区变窄就收成顶上的「筛选」按钮（手机上本来就是这样）。
- **按打开次数排序**：hold 记每份资料被真实用户打开的次数（只记份数不记人），检索先按次数、次数相同照旧；卡片右上显示「打开 N 次」。本机测试与探针不计数。

## 用到的设计知识
- **Fit-to-width** 是 PDF 阅读器（Acrobat、Chrome PDF、macOS 预览）的常用默认，窄容器里整页可读比「100%」更重要。
- **放大镜 / loupe**：看图软件与电商大图常用，比整页放大保留了上下文（你知道自己在看哪一块）。
- **容器查询（CSS Container Queries，2023 起主流浏览器都支持）**：组件按自己被放进的盒子响应，而不是按整个窗口 —— 同一个筛选栏在全屏和抽屉旁都合适。
- **让位原则（content first）**：空间不够时先收导航与次要控件，不压主内容。

## 备选方案与取舍
| 方案 | 结论 |
|---|---|
| 默认 100% 缩放 | 不用：抽屉里只能看到页面中间一块（owner 说的「只显示局部」） |
| 点击放大（每点一次放大一档） | 不用：会丢掉位置感，owner 要的是「一下子就放大」 |
| 开抽屉时一律收导航 | 不用：2000 宽的屏上宽度够，强收反而多一步 |
| 用「被搜到的次数」排序 | 不用：被搜到 ≠ 被需要，热门词会把无关条目顶上来；用「被打开的次数」 |

## 需要负责人做的判断
「搜索次数」我按**打开次数**实现（有人真的点开看了才算一次）。如果你指的是「被搜到的次数」，告诉我改。
