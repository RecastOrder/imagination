# 018 Grasshopper 生成器接进项目「分析工具」

## 要解决的问题
Grasshopper 生成器原来只在旧站 cairn.recastorder.com/app/gh 上能用。项目「分析工具」里那张卡片写着“已有 · 待接入”，点不了。要让它在新平台上就能交单、看结果。

## 方案

```
项目 › 分析工具 › Grasshopper 生成器
  ┌──────────────────────────────────────────────┐
  │ [需求描述………………………………………]            │
  │ [生成]  一次只跑一单…不会自动存进项目文件夹…     │
  │ 我的生成记录                                    │
  │  ┌ 一排竖向遮阳百叶…          [生成中 ⟳] ┐      │
  │  └ 11:09 提交                              ┘      │
  │  ┌ …                            [已完成] ┐      │
  │  │ [连线图] [透视图]                      │      │
  │  │ [下载 .gh] [下载 .3dm] ✓对照过需求      │      │
  └──────────────────────────────────────────────┘

浏览器 ── /api/gh/requests ──▶ 本平台服务器 ── 本机直连 ──▶ Cairn /api/svc/gh/requests ◀── hold 上的 worker 领单、回传文件
          （登录 + tool_gh 权限）   服务令牌 + “替谁”        谁看哪一单由 Cairn 判
```

- 和对话同一条服务口：本平台不存生成记录，只转发；记录与文件的正本在 Cairn（旧站和新站看到的是同一份）。
- 权限两层：本平台的功能权限 `tool_gh`（没有 ⇒ 卡片显示“未开通”，接口 403）；Cairn 名单（不在名单 ⇒ 页面提示“还没有开通”）。
- 排队 / 生成中每 10 秒自动刷新，都结束了就停。

## 用到的设计知识
- **系统状态可见**（Nielsen 第 1 条）：一单要 5–10 分钟，所以四种状态（排队中 · 生成中 · 已完成 · 没有成功）都有明确标签，失败写出原因。
- **诚实的承诺**：页面顶部那句“结果保存回项目文件夹”对这个工具暂时不成立，卡片里单独说明。

## 备选方案与取舍
| 方案 | 结论 |
|---|---|
| 在对话里加 Grasshopper 模式（spec 102 的三种模式之一） | 暂不做：对话模式还没定（见 017 待你决定），先放在项目工具里 |
| 结果自动存进项目 02 设计过程 | 下一刀：要先定“存哪个项目、谁能看”，这一刀先让它能用 |
| 浏览器直接调旧站接口 | 不用：旧站只认它自己的登录，而且会跨站 |
