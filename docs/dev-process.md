# UI 开发流程：每个阶段定下什么

| 阶段 | 要定下来（冻结）的内容 | 产出 | 验收 | 状态 |
|---|---|---|---|---|
| 0 定义 | 核心任务 Top 5、信息架构、权限模型（访客 / 成员 / 管理员） | 信息架构图、用户流程、权限表 | 每个页面能说清“为谁、做什么” | 进行中 |
| 1 线框 | 关键页面布局、状态矩阵（组件 × 状态） | 低保真线框 / 可点击雏形 | 每种状态都有画面 | 进行中（本仓库雏形） |
| 2 基础系统 | 令牌、字体、L1 基础组件、暗色模式 | `globals.css`、`/design` 样张 | 页面中没有原始色值 | ✓ v0.2（新增 highlight / paper / ink 令牌） |
| 3 业务组件 | AppShell、Thread、Composer、Block 结构、筛选、预览；v0.2：模式、笔记本、阅读器双视图、权限、上传 | 组件 + 样张 + 前后端数据约定 | 前后端对 Block 结构达成一致 | ✓ v0.2（演示数据） |
| 4 页面与响应式 | 首页、对话、资料库、阅读页的桌面 / 平板 / 手机形态 | 可运行原型 | 真机走通核心流程 | 待真机测试 |
| 5 用户测试 | 5 位建筑师的测试任务脚本 | 问题清单 + 优先级 | 高优先级问题全部解决 | 未开始 |
| 6 规范化 | 设计规范文档、令牌变更流程（改令牌要评审） | 规范站点 | 新人按文档能做出一致的页面 | 未开始 |

每完成一个模块，在 `docs/design-journal/` 记录一篇。

## 接后端前需要定下来的接口（v0.2 整理）

| 前端假数据 | 将来的接口 |
|---|---|
| `lib/chat/mock-responder.ts` | 对话接口：输入问题 + 模式 + 范围（笔记本），流式返回 Block 列表 |
| `lib/sources/mock.ts` | 资料检索 / 详情接口，含权威等级、规范状态、段落 ↔ 页码映射 |
| `lib/notebook/store.ts` | 笔记本、笔记、高亮的增删改查 |
| `components/files/use-uploader.ts` 的上传部分 | 分块上传：查重（指纹）→ 上传块（带块哈希）→ 合并校验；百度网盘 OAuth + 拉取任务 |
| `lib/auth/permissions.ts` | 角色模板、成员权限；**所有接口在服务端校验权限** |
| `lib/server/otp.ts`、`lib/server/prefs.ts`（内存） | 验证码存 Redis、偏好存数据库；`sendCodeEmail` 接邮件服务 |
